# Эксперименты роста «СварДок Заявка»

Статус: рабочий backlog  
Горизонт: 60 дней после выполнения условий закрытой беты  
Дата актуализации: 31 августа 2026 года

## 1. Правило эксперимента

Каждый тест фиксируется до запуска:

```text
Сегмент → триггер → сообщение → канал → целевое событие → порог решения
```

Один тест проверяет одну основную гипотезу. Клики и реакции не считаются
доказательством спроса; минимальное продуктовое доказательство — скачивание
черновика целевым пользователем после успешной проверки.

## 2. Очередь тестов

| ID | Приоритет | Гипотеза | Действие | Сигнал успеха | Стоп-правило |
|---|---:|---|---|---|---|
| E01 | P0 | Главные сварщики понимают ценность без слова «ИИ» | 5 наблюдаемых прохождений с сообщением «проверяемый черновик» | 4 из 5 своими словами верно объясняют результат | 3 из 5 считают сервис официальным или ожидают гарантию |
| E02 | P0 | Возврат на уточнение — самый сильный триггер | 15 интервью с разметкой последних реальных задач | Триггер повторяется минимум у 5 респондентов | Нет повторяющегося сценария — сегментировать заново |
| E03 | P0 | Лид-гейт до результата снижает доверие | В закрытой бете не требовать контакт до DOCX; после показать добровольный CTA | Есть скачивания и хотя бы один добровольный контакт | Контакт обязателен только при отдельной услуге |
| E04 | P0 | Тёплое персональное приглашение даст первые завершения | 30 приглашений по существующим деловым контактам | 10 стартов и 5 скачиваний | После 30 приглашений нет ни одного старта |

| E06 | P1 | Узкие поисковые запросы приводят пользователей с задачей сейчас | Две группы точных запросов в Яндекс Поиске | Есть скачивание и подтверждённая роль пользователя | 100 релевантных переходов без скачивания |

| E09 | P2 | Разбор «до/после» лучше общей карусели объясняет продукт | Синтетический кейс и обычная информационная карусель | Больше стартов на 100 релевантных просмотров | Остановить формат после двух размещений без стартов |
| E10 | P2 | Экспертная приёмная создаёт вопросы для контента и беты | Одна 30-минутная сессия | 5 целевых участников, 3 новых вопроса, 1 старт | Нет целевых регистраций после персональных приглашений |
| E11 | P2 | Название «СварДок» понятно без пояснения | Тест на 5–7 представителях ICP: смысл, доверие, произношение | 5 человек связывают имя со сварочными документами | Повторяющаяся негативная ассоциация или путаница |
| E12 | P3 | Следующий спрос — проверка готового пакета, а не новая форма | Кнопка «Проверить имеющийся черновик» как честный waitlist после результата | 20% пользователей результата выбирают интерес | Не реализовывать по кликам без 5 интервью |

## 3. Последовательность на 60 дней

### Недели 1–2 — язык и доверие

- E01, E02, E11;
- 15 интервью, 5 наблюдаемых прохождений;
- уточнение посадочного сообщения и причин отказа;
- проверка названия, политики данных и дисклеймеров.

Выход этапа: пользователь понимает продукт без устного объяснения и не считает
его официальным сервисом.

### Недели 3–4 — закрытая активация

- E03, E04, E05;
- исправление трёх главных точек отвалов;
- первый обезличенный разбор «до/после»;
- базовые события воронки без содержимого заявки.

Выход этапа: минимум 10 целевых стартов и 5 скачиваний.

### Недели 5–6 — сформированный спрос

- E06, E07, E09;
- точный поиск с ограниченным бюджетом;
- четыре страницы под конкретные задачи;
- два точечных размещения, не массовый охват.

Выход этапа: известен хотя бы один канал, который приводит целевое скачивание.

### Недели 7–8 — дистрибуция и расширение

- E08, E10, E12;
- один партнёрский пилот;
- решение о следующем модуле по интервью, не по числу кликов;
- отчёт: сегмент, триггер, сообщение, стоимость активации, ограничения.

Выход этапа: решение `масштабировать / изменить сегмент / остановить канал`.

## 4. Карточка результата

Для каждого теста сохраняется:

```markdown
### E__ — название

- Период:
- Сегмент и источник:
- Гипотеза:
- Единственная изменяемая переменная:
- Основная метрика:
- Результат:
- Что узнали:
- Решение: продолжить / изменить / остановить
- Следующий тест:
```

Не сохраняются содержимое заявок, персональные данные и технические сведения
предприятия. Цитата респондента публикуется только с его разрешения либо в
обезличенном пересказе.

## 5. Контрольная панель пилота

| Метрика | Цель 60 дней | Назначение |
|---|---:|---|
| Интервью с ICP | 15 | Проверить язык и сценарии |
| Наблюдаемые прохождения | 5 | Найти проблемы формы |
| Скачанные черновики | 30 | Подтвердить полезное использование |
| Добровольные контакты | 10 | Проверить коммерческий интерес |
| Содержательные консультации | 5 | Проверить качество спроса |
| Партнёрские переговоры | 2 | Проверить модель дистрибуции |
| Жалобы на ложную официальность | 0 | Защитить доверие и бренд |

Цели — пороги управленческого решения, а не прогноз. Если пользователи не
доходят до скачивания, увеличение рекламного бюджета запрещено до исправления
продукта или сообщения.

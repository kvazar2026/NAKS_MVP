# ADR 0004: Два уровня правил валидации — достоверные (блокирующие) и черновые (предупреждения)

## Статус

Принято (интервью по `naks-mvp-core`, см. `.scratch/naks-mvp-core/`).

## Контекст

`naks-checklist-monetization.md` описывает содержательные типовые ошибки
подготовки заявок (смешение аттестации технологии и оборудования, отсутствие
привязки к ОПО и т.д.), но это качественное описание, а не проверенный
формальный источник допустимых значений и несовместимых комбинаций. Явного
доступа к эксперту НАКС для проверки таких правил на момент разработки MVP
нет (см. также ADR 0001 про ограничение роли LLM).

Если считать все правила из чек-листа блокирующими наравне со структурной
валидацией (обязательные поля, форматы), продукт будет выдавать
непроверенные инженерные суждения за окончательные — риск, прямо запрещённый
`AGENTS.md`.

## Решение

Правила валидации разделены на два уровня в едином справочнике (поля: код,
направление, условие, уровень `error`/`warning`, объяснение, источник,
статус проверки, дата последней проверки):

- **Достоверные (`error`, блокируют отправку)** — обязательность полей,
  формат ИНН/телефона/email, ограничения длины, принадлежность значения
  справочнику, структурная валидность запроса.
- **Черновые (`warning`, не блокируют)** — правила, выведенные из
  `naks-checklist-monetization.md`, с пометкой «предварительная
  автоматическая проверка, требует подтверждения специалистом или АЦ».

LLM в проверке несовместимых инженерных комбинаций не участвует как источник
истины (см. ADR 0001) — он используется только для объяснения неоднозначностей
пользователю понятным языком.

## Последствия

- Пользователь может отправить заявку с черновыми предупреждениями — это
  осознанно, а не баг валидации.
- Каждое черновое правило обязано нести источник и статус проверки — правило
  без этих полей не должно попадать в справочник.
- Будущему читателю: если правило блокирует отправку, оно обязано быть в
  категории «достоверное» с проверяемым источником; добавление нового
  блокирующего правила «на глаз» нарушает это ADR.

# План выполнения MVP: AI-ядро преквалификации НАКС

Источник концепции: `naks-launch-plan.md` (ФАЗА 2, разделы 1–2). Этот документ детализирует
только техническое ядро — опросник и генерацию документов — до уровня конкретных задач.

## Объём (Scope)

**В MVP входит:**
- Опросник для завода (5 шагов, см. «Пользовательский путь» ниже).
- Расчёт режимов сварки через LLM по мастер-промпту (эквивалент углерода, токи,
  напряжение, защитный газ) для 3–5 марок стали (09Г2С, 12Х18Н10Т, Ст3).
- Генерация заполненных `.docx`-документов (заявка, pWPS) из официальных шаблонов АЦ.

**Сознательно вне MVP** (см. `naks-launch-plan.md`, ФАЗА 1–3):
- CRM-интеграция и лидогенерация для «Квазара» (webhook'и, теги «горячий лид»).
- Переговоры с АЦ, встраивание виджета/iframe на сайт АЦ.
- `naks_parser.py` и реестр АТС — не связаны с генерацией документов, отдельная задача.

## Стек (зафиксирован по `naks-launch-plan.md`)

- **Backend:** Python + FastAPI.
- **Frontend:** лёгкий SPA-виджет (React или Vue — выбрать конкретный фреймворк перед Этапом 4).
- **LLM:** API GPT-4o или Claude 3.5 Sonnet через один абстрактный клиент (провайдер — открытый вопрос, см. ниже).
- **Генерация документов:** `python-docx` поверх официальных Word-шаблонов АЦ.
- **Хранение:** на старте без БД (запрос → ответ без персистентности); при необходимости логирования заявок — SQLite.

## Пользовательский путь (User Flow)

1. Ввод ИНН (автозаполнение названия завода через DaData/Контур — опционально, можно ручное поле в MVP).
2. Опросник (5 шагов): группа ОПО, марка стали + толщина, способ сварки, оборудование.
3. Экран ожидания (расчёт через LLM).
4. Экран результата и скачивание готового `.docx`-пакета.

## Этапы

### Этап 0 — Подготовка данных и промпта (без кода)
- Собрать эталонные значения режимов сварки, C_экв и допусков по ГОСТ/РД для 3–5 марок стали.
- Получить официальные Word-шаблоны заявки и pWPS от АЦ (или рабочий образец с плейсхолдерами).
- **Готово, когда:** есть таблица эталонов + минимум 1 `.docx`-шаблон с плейсхолдерами.

### Этап 1 — Backend-скелет
- Инициализировать FastAPI-проект в `backend/` (структура, `requirements.txt`/`pyproject.toml`).
- Эндпоинт `POST /survey`: принимает JSON опросника, возвращает расчёт по таблице Этапа 0 (без LLM — детерминированная заглушка).
- **Готово, когда:** сервис запускается локально, есть тест на 1 сценарий.

### Этап 2 — Интеграция LLM
- Мастер-промпт с базой ГОСТов/РД для выбранных марок стали.
- Клиент LLM (провайдер конфигурируется), вызов с данными опросника → структурированный JSON.
- Валидация ответа LLM по JSON-схеме, явная ошибка при некорректном ответе (без тихого фолбэка на случайные значения).
- **Готово, когда:** для 5 тестовых входов LLM возвращает валидный JSON; расхождения с эталоном Этапа 0 задокументированы.

### Этап 3 — Генерация документов
- Заполнение шаблонов заявки и pWPS данными из JSON через `python-docx`.
- Эндпоинт `POST /generate`, отдающий готовый `.docx`.
- **Готово, когда:** сгенерированный файл открывается в Word, поля соответствуют входным данным.

### Этап 4 — Frontend-опросник
- Выбрать фреймворк (React/Vue), собрать SPA: 5 шагов опросника + экран ожидания + экран результата.
- Интеграция с backend (`/survey` → `/generate`).
- **Готово, когда:** сквозной сценарий в браузере от ввода данных до скачивания `.docx` работает целиком.

### Этап 5 — Ручное тестирование «в стол»
- Прогнать 5–10 синтетических сценариев, сверяя с чек-листом типовых ошибок из
  `naks-checklist-monetization.md` (смешение технологии/оборудования, отсутствие привязки к ОПО и т.д.).
- **Готово, когда:** есть список расхождений/багов с приоритетами.

## Открытые вопросы и риски

- **Провайдер LLM** (GPT-4o vs Claude 3.5 Sonnet) и стоимость API — уточнить до Этапа 2.
- **Фреймворк фронтенда** (React vs Vue) — не зафиксирован, решить перед Этапом 4.
- **Права на шаблоны АЦ**: официальные Word-шаблоны нужно получить легально, самостоятельное копирование без согласования недопустимо.
- **Юридический статус результатов**: сгенерированные документы — черновик/проект, не гарантия прохождения аттестации (см. `AGENTS.md`, раздел «Безопасность и качество предметных данных»).
- **Точность мастер-промпта** не подтверждена без проверки квалифицированным технологом-сварщиком.

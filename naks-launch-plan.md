## ФАЗА 2. Технический план создания продукта (Архитектура)

Мы создаем модульную систему из 3 частей.

### 1. Frontend (Клиентская часть для главного сварщика)
**Технология:** Легкий React/Vue виджет или лендинг на поддомене АЦ (например, `ai.naks-perm.ru`, хостинг на вашей стороне).
**Пользовательский путь (User Flow):**
1. Ввод ИНН (автозаполнение названия завода через API Контур/DaData).
2. Опросник (5 шагов):
   - Группа ОПО (выпадающий список: НГДО, КО, СК...)
   - Марка стали (автосаджест) и толщина
   - Способ сварки (РАД, МП)
   - *Скрытый лидген для «Квазара»:* "Какое оборудование будете использовать?"
3. Экран загрузки: *"AI-Инженер рассчитывает эквивалент углерода и подбирает режимы..."* (Крутится анимация 5-10 секунд).
4. Экран результата: *"Пакет готов! Найдено 0 ошибок. Для генерации чистовых документов в Word оставьте телефон и Email."*

### 2. Backend и AI-ядро (Под капотом)
**Технология:** Python (FastAPI) + API LLM (GPT-4o / Claude 3.5 Sonnet).
1. Бэкенд получает JSON с ответами завода.
2. Отправляет данные в LLM вместе с **Мастер-промптом** (база ГОСТов и РД).
3. LLM возвращает JSON с рассчитанными режимами (токи, напряжение, $C_{экв}$, газы).
4. Python-библиотека `python-docx` берет этот JSON и **вставляет данные в официальные Word-шаблоны АЦ**.

### 3. CRM и Лидогенерация
1. Сгенерированные `.docx` файлы отправляются на почту главному сварщику (или инспектору АЦ).
2. **Лид (ИНН, телефон, марка оборудования)** мгновенно падает в CRM-систему компании «Квазар» с тегом *«Горячий лид: Готовит НАКС, Пермь»*.

Ваш питч (на правах гендиректора «Квазара» с 15-летним стажем) строится на 3 аргументах:

## ФАЗА 4. Дорожная карта запуска (4 недели)

### Неделя 1: Разработка прототипа (MVP)
- Регистрация сервера/инфраструктуры.
- Сборка опросника (на базе Marquiz, Typeform или кастомного HTML).
- Настройка Мастер-промпта в LLM на выдачу правильных режимов для 5 самых популярных марок сталей (09Г2С, 12Х18Н10Т, Ст3).

### Неделя 2: Интеграция генерации документов
- Написание Python-скрипта для автозаполнения `.docx` шаблонов.
- Настройка Webhook'ов в CRM «Квазар».
- Тестирование «в стол»: симуляция ввода данных $\rightarrow$ получение готового пакета.

### Неделя 3: Переговоры с АЦ
- Встреча с директором Пермского АЦ НАКС.
- Демонстрация работы прототипа в реальном времени.
- Согласование размещения HTML-кнопки (Iframe) на сайте АЦ или настройки редиректа на поддомен.

### Неделя 4: Запуск и первые B2B-сделки
- Кнопка появляется на сайте АЦ НАКС.
- В CRM поступают первые данные заводов.
- Отдел продаж «Квазара» совершает перехват сделки: *"Иван Иванович, видим, вы готовите технологию сварки 12Х18Н10Т через портал НАКС. Под эту задачу вам потребуются новые TIG-источники. Можем отгрузить завтра, а пакет НАКС сделаем в подарок"*.

# 05 — Встраивание через iframe

**What to build:** Страница виджета из тикета 02 встраивается через
`<iframe>` на отдельной тестовой HTML-странице из репозитория, автоматически
подстраивает высоту через `postMessage` на настроенный целевой `origin`,
принимает тему и идентификатор партнёра через безопасные параметры из
заранее определённого перечня (неизвестный partner-id — откат на демо-
конфигурацию с уведомлением, не ошибка), и отклоняет `postMessage` от
непредусмотренных `origin`.

**Comments:**

Реализовано. Модуль встраивания — `frontend/src/embedding/`
(`embedConfig.ts` — параметры, `parentMessaging.ts` — контракт postMessage,
`EmbedContainer.tsx` — оболочка). Тестовая страница —
`frontend/public/embed-demo.html`, попадает в сборку и доступна по
`/embed-demo.html`. Пример встраивания продублирован в README.

Решения, которые стоит знать:

- **Целевой origin определяется по referrer, а не берётся из параметра.**
  Параметр, который задаёт встраивающая сторона, не даёт защиты — кто угодно,
  кто вставил iframe, поставит туда что захочет. Виджет берёт origin
  хост-страницы из referrer и отправляет сообщения, только если он есть в
  списке разрешённых. Неизвестный хост не получает ничего: `*` не
  используется никогда. Это fail-closed — при неверной настройке ломается
  авторесайз, а не утекает размер содержимого на чужую страницу.
- **Список разрешённых origin — переменная сборки**
  (`WIDGET_ALLOWED_PARENT_ORIGINS` → build arg `VITE_ALLOWED_PARENT_ORIGINS`),
  потому что Vite вшивает `VITE_*` в бандл. Значит после её изменения нужен
  `docker compose build frontend`, а не рестарт — это отдельно написано в
  `.env.example` и README, иначе на этом легко потерять время. По умолчанию
  пусто = только собственный origin, чего хватает демо-странице.
- **Входящее сообщение одно** — `naks-widget:request-size` (хост просит
  прислать высоту заново после того, как перестроил свою вёрстку). Проверка
  `event.origin` идёт до разбора содержимого сообщения.
- **`SurveyWidget` про iframe ничего не знает** — оболочка добавлена уровнем
  выше, в `App.tsx`. Второй способ встраивания (JS-сниппет), если появится,
  не потребует правок логики формы.
- **`useMemo` в `App.tsx` не косметика:** без него массив разрешённых origin
  получал бы новую идентичность на каждый рендер, и `useEffect` пересоздавал
  бы `ResizeObserver` и слушатель сообщений при каждом изменении состояния
  формы.

Проверено в реальном Chromium, не только в jsdom: на `/embed-demo.html`
высота iframe выставляется в 1958 px, при росте содержимого на 600 px
пересчитывается в 2558 px; referrer доходит до виджета, поэтому целевой
origin резолвится; `?theme=neon` откатывается на `light`;
`?partner=unknown-partner` показывает уведомление. Ни один запрос страницы не
возвращает 4xx.

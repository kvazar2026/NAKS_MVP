# 04 — Реальный AnthropicProvider

**What to build:** При наличии `ANTHROPIC_API_KEY` backend реально вызывает
Anthropic API (`claude-sonnet-5`) для нормализации/классификации вместо
`MockProvider`, соблюдая тот же контракт `LLMProvider` и правило минимизации
данных. При отсутствии ключа поведение не меняется относительно тикетов 02/03
(работает `MockProvider`).

**Blocked by:** 02.

**Status:** ready-for-agent

- [ ] `AnthropicProvider` реализует `LLMProvider`, отправляя в Anthropic API
      только классификационно-значимые поля из контракта тикета 01 — тест
      подтверждает, что в исходящем запросе никогда нет ИНН/адреса/ФИО/
      телефона/email.
- [ ] Сырой JSON-ответ Anthropic проверяется по строгой схеме (например,
      Pydantic-модель, соответствующая контракту `LLMProvider`) перед
      использованием; некорректный/неожиданный ответ трактуется как ошибка,
      а не молча приводится к «правдоподобному» виду.
- [ ] Классифицированные `AnthropicProvider` значения проходят ту же
      повторную проверку по справочникам, что и значения от `MockProvider`
      (правило из тикета 02 без исключений для «настоящего» провайдера).
- [ ] Выбор реализации: без `ANTHROPIC_API_KEY` — автоматически
      `MockProvider`; при наличии ключа — `AnthropicProvider`
      (задокументировано в `.env.example`, который этот тикет дополняет).
- [ ] Общий набор контрактных тестов `LLMProvider` (из тикетов 01/02)
      прогоняется на `AnthropicProvider` только при наличии
      `ANTHROPIC_API_KEY` в тестовом окружении; иначе эта часть пропускается,
      а не падает.
- [ ] Тест симулирует некорректный ответ Anthropic (через заглушку HTTP-слоя)
      и подтверждает, что строгая схема отклоняет его безопасной ошибкой, а
      не падением или тихой порчей данных.

# 06 — Rate limiting и защита эндпоинтов

**What to build:** `/api/v1/survey/validate` и `/api/v1/documents/generate`
защищены настраиваемым лимитом запросов по IP (на `/generate` — строже),
лимитом размера тела запроса, таймаутом обработки, лимитом параллельных
генераций и безопасными обобщёнными ошибками — проверено против настоящей
топологии reverse proxy из тикета Docker Compose, а не только против
симулированных заголовков.

**Blocked by:** 02, 07.

**Status:** ready-for-agent

- [ ] Лимит запросов по IP на `/api/v1/survey/validate` и отдельный, более
      строгий, настраиваемый лимит на `/api/v1/documents/generate` — оба
      конфигурируются через переменные окружения с документированными
      MVP-значениями по умолчанию.
- [ ] Максимальный размер тела запроса и таймаут обработки — запросы,
      превышающие их, отклоняются с общей ошибкой без внутренних деталей в
      ответе.
- [ ] Число параллельных выполнений `/documents/generate` ограничено
      (настраивается), при превышении — общая ошибка/backpressure-ответ.
- [ ] Настройка доверенных reverse-proxy адресов (кому разрешено
      устанавливать `X-Forwarded-For`) — через переменные окружения;
      `X-Forwarded-For` от недоверенного источника игнорируется, используется
      IP прямого соединения (проверено тестом с симулированными заголовками
      от доверенного и недоверенного источника).
- [ ] Хранилище счётчиков rate limiting — in-memory; это ограничение (работает
      только для одного процесса/воркера, для нескольких воркеров нужно общее
      хранилище, например Redis) явно задокументировано в README/комментариях
      конфигурации, а не подразумевается по умолчанию.
- [ ] Проверено против настоящего reverse proxy из тикета Docker Compose:
      ручная или скриптовая проверка подтверждает, что обработка
      `X-Forwarded-For` и лимитирование по IP корректно работают, когда
      запросы реально проходят через настроенный прокси, а не только в
      юнит-тестах с симулированными заголовками.
- [ ] `.env.example` дополнен всеми новыми переменными этого тикета.
- [ ] pytest: превышение лимита на `/survey/validate` → `429`; превышение
      более строгого лимита на `/generate` → `429`; слишком большое тело
      запроса отклоняется; симулированные доверенный/недоверенный прокси
      ведут себя как специфицировано.

# 02 — Первый сквозной пользовательский сценарий

**What to build:** Пользователь открывает страницу виджета напрямую (без
iframe — это тикет 05), заполняет полный набор общих полей и полей по
направлению «оборудование», видит блокирующие ошибки по обязательности,
формату и справочникам, видит «материалы»/«сварщики» как неактивные «скоро»,
ставит согласие рядом с демо-баннером, отправляет заявку — backend
нормализует технические поля через `MockProvider` (без реального ключа),
независимо перепроверяет данные на `/documents/generate` (никогда не веря
клиентскому «уже провалидировано»), заполняет единственный демо-шаблон и
отдаёт настоящий, открываемый `.docx`. Ничего не сохраняется на диске после
ответа, в логах нет персональных данных.

**Blocked by:** 01.

**Status:** done

- [x] Frontend отображает полный опросник: общие поля (ИНН, название,
      адрес, контактное лицо/должность/телефон/email, выбор АЦ — единственный
      пункт «Демо-АЦ», направление аттестации с активным «оборудование» и
      неактивными «скоро» «материалы»/«сварщики», группа ОПО, регион) + поля
      по оборудованию (тип, марка, модель, изготовитель, способ сварки,
      количество, заводские номера, назначение) + согласие с демо-баннером.
- [x] Кнопка отправки неактивна, пока не отмечено согласие.
- [x] `POST /api/v1/survey/validate` реализован: сначала прогоняет
      детерминированные блокирующие правила (обязательность, форматы ИНН/
      телефона/email, длины, принадлежность справочникам, структура запроса);
      при любой ошибке возвращает её без обращения к LLM; при успехе
      вызывает `LLMProvider` (через `MockProvider`) только с
      классификационно-значимыми полями (никогда ИНН/адрес/ФИО/телефон/
      email) и возвращает нормализованные данные.
- [x] Классифицированные LLM значения заново проверяются по тем же
      справочникам допустимых значений, прежде чем считаться валидными —
      ответ LLM не принимается на веру автоматически.
- [x] `POST /api/v1/documents/generate` независимо повторно прогоняет тот же
      набор блокирующих структурных правил на полученных данных (общий
      модуль валидации с `/survey/validate`, а не доверие клиенту) и
      отклоняет запрос с `400` при их нарушении — вне зависимости от того,
      что утверждает клиент о предыдущей проверке.
- [x] При успехе `/documents/generate` заполняет единственный демо-шаблон
      ((`demo`, `equipment`) из `template registry`) и отдаёт настоящий
      `.docx`-файл потоком (`Content-Disposition: attachment`).
- [x] Сгенерированный `.docx` содержит пометку «демонстрационный макет, не
      является официальным бланком АЦ».
- [x] Ничего не сохраняется: ни содержимое заявки, ни сгенерированный
      документ не остаются на диске/в каком-либо хранилище после ответа
      (проверено тестом).
- [x] Backend логирует только обезличенные технические поля (время
      обработки, направление, код результата, тип ошибки) — никаких
      реквизитов и значений полей заявки.
- [x] Экран результата на frontend показывает рабочую кнопку скачивания;
      ошибочные состояния показывают общее нетехническое сообщение.
- [x] pytest покрывает: валидная отправка → успех; отсутствие обязательного
      поля → блокирующая ошибка без вызова LLM; значение вне справочника →
      блокирующая ошибка; сгенерированный `.docx` открывается заново и его
      поля соответствуют отправленным значениям; после запроса не остаётся
      временных файлов.
- [x] Vitest + RTL покрывает: рендер всех полей формы; отображение
      блокирующих ошибок; недоступность отправки без согласия; неактивность
      пунктов «материалы»/«сварщики».

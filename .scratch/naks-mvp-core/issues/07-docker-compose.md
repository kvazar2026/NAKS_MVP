# 07 — Docker Compose

**What to build:** Одна команда `docker compose up` поднимает backend,
frontend и reverse proxy перед ними, все с healthcheck'ами, используя
документированные переменные окружения. Контейнеризуется то, что backend/
frontend отдают на момент выполнения тикета (начиная с каркаса из тикета 01,
и подхватывая реальную функциональность тикетов 02+ по мере их появления в
той же ветке/main).

**Blocked by:** 01.

**Status:** ready-for-agent

- [ ] Отдельный `Dockerfile` для backend и для frontend, оба собираются с
      чистого чекаута.
- [ ] `docker-compose.yml` связывает backend + frontend + reverse proxy
      (например, nginx), пригодный для последующей проверки iframe-сценария,
      с healthcheck для backend и frontend.
- [ ] `.env.example` документирует все переменные окружения, необходимые для
      запуска compose-стека на момент этого тикета; README указывает, что
      последующие тикеты, добавляющие новые переменные, обязаны дополнять
      этот файл.
- [ ] README описывает: запуск локально одной командой через Docker Compose,
      и отдельно — инструкцию «как задеплоить на свой сервер позже» (без
      попытки реального публичного деплоя в этом тикете).
- [ ] `docker compose up` успешно стартует с чистого клона (только
      `.env.example`, скопированный в `.env`), health-эндпоинты отвечают
      через сервисы, поднятые compose.

**Comments:**

Rate limiting (тикет 06) блокируется этим тикетом — его проверка против
настоящего reverse proxy возможна только после того, как этот прокси здесь
появится.

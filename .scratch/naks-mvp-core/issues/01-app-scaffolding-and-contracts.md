# 01 — Каркас приложений и базовые контракты

**What to build:** Разработчик может склонировать репозиторий, поставить
зависимости backend и frontend, запустить каждый одной документированной
командой, получить ответ от health-эндпоинта каждого сервиса и увидеть уже
на месте базовые абстракции (интерфейс `LLMProvider`, реестр шаблонов,
реестр АЦ/направлений, Pydantic-модели запросов/ответов будущих эндпоинтов)
как типизированный, покрытый тестовой инфраструктурой каркас — без реальной
бизнес-логики опросника.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] FastAPI-проект в `backend/`: `requirements.txt` + `requirements-dev.txt`,
      `.venv`, версии зафиксированы, установка описана в README, без
      глобальных пакетов.
- [ ] React + TypeScript проект в `frontend/` со своим менеджером
      зависимостей (npm) и документированной командой запуска.
- [ ] Оба приложения поднимаются одной документированной командой каждое;
      backend отдаёт `GET /health`, frontend отдаёт загружаемую (пусть и
      пустую) корневую страницу.
- [ ] Pydantic-модели запроса/ответа для будущих `/api/v1/survey/validate` и
      `/api/v1/documents/generate` покрывают полный набор общих и
      специфичных для «оборудования» полей из User Stories спецификации.
- [ ] Определён абстрактный интерфейс `LLMProvider` по контракту из
      спецификации: на вход — только поля, требующие
      нормализации/классификации (никогда ИНН/адрес/ФИО/телефон/email); на
      выход — нормализованное значение по полю + отметка
      «нормализовано»/«нужна проверка» + список замеченных неоднозначностей.
      Конкретная реализация не обязательна в этом тикете.
- [ ] Определены структуры `template registry` (код АЦ, направление →
      шаблон) и реестра АЦ, механизм загрузки конфигурации, с единственной
      MVP-записью (`demo`, `equipment`) — сам файл демо-шаблона `.docx`
      может появиться позже, в тикете 02.
- [ ] Настроена тестовая инфраструктура backend (`pytest`), минимум один
      проходящий тест (например, на health-эндпоинт).
- [ ] Настроена тестовая инфраструктура frontend (`Vitest` + `React Testing
      Library`), минимум один проходящий тест.
- [ ] README описывает: установку зависимостей, запуск backend, запуск
      frontend, запуск обоих тестовых наборов.
- [ ] Бизнес-логика (реальные поля опросника, правила валидации, генерация
      `.docx`) в этот тикет не входит — это тикет 02.
